# Decision Log (결정 기록)

> 가이드 원칙 4 "Decisions Matter". 형식: **처음 생각 → 확인한 내용 → 바뀐 판단**. 발표의 "Key Decisions"와 개인 회고 재료가 된다.
> 결정할 때마다 한 줄씩 추가하자. 누가, 언제 정했는지도 적기.

| # | 날짜 | 주제 | 처음 생각 | 확인한 내용 | 바뀐 판단 / 결정 | 결정한 사람 |
|---|---|---|---|---|---|---|
| D1 | 11/9 | 아이템 방향 | 주소를 넣으면 위험도를 알려주는 "전세사기 위험도 계산기" | HUG 안심전세 앱 등이 이미 무료로 시세·위험도·악성 임대인 조회를 제공. 그런데 사회초년생은 앱을 모르거나 등기부를 읽지 못함 (팀 내 확인: ___명 중 ___명) | 계산이 아니라 **"이해하고 행동하게 돕는" 첫 전세 계약 가이드**. 기존 서비스로 이어주는 입문 도구 | 공감 팀 |
| D2 | 11/9 | AI 역할 | AI가 위험도를 판단 | AI 판단은 결과가 매번 달라질 수 있고 이유 설명이 어려움. 가이드상 AI 기능은 필수 아님 | **위험 점수는 규칙 기반**, AI는 쉬운 말 설명·질문·특약 문구만. 실패 시 템플릿 | 공감 팀 |
| D3 | 11/9 | 데이터 범위 | 테이블 7개 (회원, 매물, 실거래가 포함) | 자동 매물·실거래가 수집은 핵심 흐름이 아니지만, 사용자가 진단 입력을 나중에 확인하고 수정하려면 회원과 진단 기록의 연결이 필요함 | 시세와 매물 정보는 직접 입력하고 실거래가 API는 제외. `users`를 포함한 5개 테이블로 구성하고 로그인 회원의 진단 입력·답변을 서버 DB에 저장 | 공감 팀 |
| D3-1 | 11/9 | 오늘 범위 | 메인 기능 3개 + AI를 이틀 동안 | 실제 개발 시간은 오늘 13~17시 4시간. ①등기부 읽기와 ②결과 안내는 사용자 입장에서 한 흐름 | **오늘 17시까지 기능 2개 완성**(등기부 진단, 계약 일정표). AI는 템플릿으로 두고 17시 이후/내일 | 팀장 |
| D3-2 | 11/9 | 로그인 범위 | 로그인은 범위 밖이거나 진단 전에 필수로 요구 | 회원가입을 먼저 요구하면 일반 사용자가 거부감을 느낄 수 있음. 반면 여러 매물의 입력을 저장하고 `UNKNOWN` 답변을 확인한 뒤 수정하려면 계정이 필요함 | **로그인은 선택.** 비로그인도 진단·결과·일정표를 모두 사용한다. 로그인 회원은 진단 원본 입력과 답변을 서버에 저장하고 마이페이지에서 수정 후 규칙 기반으로 재검토한다 | 공감 팀 |
| D3-3 | 11/9 | OCR 기반 진단 | 사용자가 서류를 읽고 질문 10개에 직접 답함 | 첨부 서류에서 확인할 수 있는 항목은 먼저 추출할 수 있음 | 주소·서류 첨부 후 OCR로 답을 채우고, 정보가 충분하면 금액 입력으로, 부족하면 미확인 질문만으로 이동한다. 점수는 기존 규칙으로 계산한다. 업로드 계약과 보관 정책은 별도 결정 (#10) | 공감 팀 |
| D4 | 11/9 | 기술 스택 | 새 기술도 고려 | 순수 개발 시간 4시간. 새 기술을 배우면 시간이 사라짐. 팀이 이미 배운 것 기준 | **Spring Boot 3 + JPA / React + Vite / MySQL 8**. 배포 없이 발표 노트북에서 로컬 실행 | 공감 팀 |
| D5 | 11/9 | 팀·프로젝트 이름 | 팀 이름과 프로젝트 이름 후보 검토 | "안심"이 들어간 이름은 안심전세 앱과 헷갈리므로 피하고, 팀의 공감 지향성과 서비스의 전세 위험 대응 의미를 함께 전달할 이름이 필요함 | **팀 이름은 공감, 프로젝트 이름은 전세역전** | 공감 팀 |
